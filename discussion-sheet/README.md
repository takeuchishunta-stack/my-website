# 決算書ディスカッションシート分析ツール（社内限定）

ソニー生命の「ディスカッションシート」を参考に、決算書（貸借対照表・損益計算書等）
3期分（最低2期分）から、財務・キャッシュフロー・自社株評価・必要保障額・財務判定
スコアリングを自動算出する社内ツールです。

**非公開ページです。** サイトのナビゲーションからはリンクされていません。
URL（`/discussion-sheet/`）を直接共有してください。

## 使い方（全体の流れ）

1. Claude（このリポジトリのセッション）に、顧問先の決算書PDF（3期分、無ければ2期分）を渡す
2. 下記の「Claude 用プロンプト」をそのまま使って、JSON形式のデータを出力してもらう
3. 出来上がったJSONを `index.html` の「①データ入力」欄に貼り付けて「このデータで分析する」
4. 画面上で各観点（財務／キャッシュフロー／自社株／必要保障／スコアリング／決算情報）を確認
5. 必要に応じて「Excelダウンロード」「PDF印刷/保存」で資料化

### 出力モード（お客様向け／内部確認用）

ヘッダーの「👤 お客様向け表示」ボタンで、表示モードを切り替えられます。

- **お客様向け（既定）**：検算の根拠・閾値の転記元・「自動生成・要確認」等の社内メモは
  一切DOM/PDFに出力されません（CSSで隠すのではなく、該当箇所の生成自体をスキップする
  ため、HTMLソースやPDFのテキストを全文検索しても見つかりません）。
- **内部確認用**（ボタンをクリックして切替）：上記の社内メモに加え、ベストエフォートの
  注記等が画面・PDF印刷の両方に表示されます。顧問先に渡す前に、必ず「お客様向け」に
  戻してから印刷してください。

新しく社内向けの注記・用語を追加する場合は、直接HTMLに書かず `internalNotice(html)` /
`internalOnly(html)`（`app.js`）でラップしてください。

ローカルで動作確認する場合は、このフォルダで簡易サーバーを立ててください（`fetch`でサンプル
JSONを読み込むため、`file://` では動きません）。

```bash
cd discussion-sheet
python3 -m http.server 8080
# http://localhost:8080/index.html を開く
```

## Claude 用プロンプト（決算書PDF → JSON変換）

決算書PDFを添付したうえで、以下をそのまま貼り付けてください（2期分しかない場合は
その旨を伝えれば、2期分のJSON＝`periods`配列を2件にして出力されます）。

```
添付の決算書（3期分）を読み込んで、/home/user/my-website/discussion-sheet/
のツールに読み込ませるJSONを作成してください。
フォーマットは discussion-sheet/sample-data/sample-zou.json と
sample-myap.json の構造に厳密に合わせてください（periods配列、bs/pl/
sgaDetail/loans/officerCompensationDetail/shareholders等のキー名を
変えないこと）。

必須項目：
- companyName, industryCategory（"卸売業"|"小売サービス業"|"その他"）,
  industryDetail, capitalAmount, totalShares, treasuryShares, shareholders
- periods（古い期→新しい期の順）: 各期の bs（貸借対照表の全科目）、
  pl（損益計算書、売上原価、販管費は sgaTotal に合計値を必ず入れ、
  sgaDetail には内訳が分かる範囲で入れる）、loans（短期・長期の金融機関別
  残高。内訳書に金融機関名が無ければ lender は "(内訳未確認)" とする）、
  officerCompensationDetail、dividendsPaid
- pl.sgaFixedAccounts：sgaDetail のキーのうち「固定費」に該当する科目名を
  配列で列挙する（下記「固定費の科目分類について」を参照。費目ごとに固定/
  変動を判断し、人件費・地代家賃・リース料・保険料・減価償却費・租税公課等の
  固定費科目のみを列挙すること。これが必要保障額の①運転資金＝月額固定費×
  ヶ月数の算出対象になるため、省略せず必ず作成する）
- pl.depreciationAnnualTotal：損益計算書・販管費・製造原価の「減価償却費」
  科目の金額（実額）。取得できない場合はキー自体を省略する（0を入れない。
  未入力のまま計算すると「減価償却費未入力」の注記が自動で表示される。
  推計値で埋めないこと）
- data.preparedAssets：既加入の生命保険の解約返戻金相当額等。ヒアリング前で
  未確認の場合はキー自体を省略する（0と未確認は区別され、未確認の間は
  必要保障ページの不足金額が「準備済み資産を確認後に確定」という表示になる）
- data.officers：配列。役員（理事）情報（finalMonthlyCompensation・
  tenureYears）が未確認の場合は空配列のままにする（退職金[参考]が「未確認」
  表示になり、0円と断定されない）
- similarIndustry は A/B/C/D を null のままにしてよい
  （国税庁データは別途入力するため）

金額は決算書の記載単位（円 or 千円）をそのまま使い、JSON内の "_meta.source"
に「千円単位／円単位」を明記してください。科目の内訳が決算書に無く推定した
値は "_meta" に必ずその旨を記載してください（数値を断定的に書かない）。
```

## 固定費の科目分類（sgaFixedAccounts）について

必要保障額の「①運転資金＝月額固定費×ヶ月数」は、販管費（sgaDetail）の
全科目合計ではなく、**固定費に該当する科目だけ**を対象に算出します
（変動費まで含めると過大評価になるため）。ソニー生命の見本資料の
製造原価報告書・販管費明細では、各勘定科目に「固」（固定費）／「変」
（変動費）の区分が付されており、そのうち「固」の科目だけを合計した
ものが運転資金の算出対象です。

決算書をJSON化する際は、`pl.sgaDetail` の科目ごとに以下の基準で固定費
（`sgaFixedAccounts` に列挙する科目）かどうかを判断してください：

- **固定費の例**：常勤・非常勤を問わない人件費（給与・賞与・賞与引当金・
  退職給与引当金・法定福利費・福利厚生費・職員被服費）、地代家賃、
  リース料、保険料、諸会費、租税公課、通信費、会議費、事務費、
  図書購読費、減価償却費（建物附属設備・構築物・機械・車両・備品・
  ソフトウェア・一括償却資産 等）
- **変動費の例（sgaFixedAccountsには含めない）**：水道光熱費、修繕費、
  消耗品費・消耗器具備品費、車両費、旅費交通費、広告宣伝費、
  接待交際費、寄付金、控除対象外消費税、外注費・委託費（検査委託費・
  清掃委託費等）、研修費、給食材料費、雑費 等

業種によって妥当な区分は変わり得るため、個別の判断が必要な科目が
あれば `_meta` にその旨を記載してください。`sgaFixedAccounts` を
省略した場合は、後方互換のため `fixedCostAnnualTotal`（手入力の年間
固定費総額。無ければ販管費合計）にフォールバックしますが、新規データは
必ず `sgaFixedAccounts` で科目ベースの分類を行ってください。

CFページの「固定費の内訳」表（`renderSgaTable`）は、この `sgaFixedAccounts`
が指定されている場合、その科目だけを金額の大きい順に表示します
（上位8科目＋その他）。

## 自社株評価（類似業種比準価額）について

類似業種比準価額の算出には、国税庁が業種目ごとに公表している

- A：類似業種の株価
- B：類似業種の1株(50円)当たりの年配当金額
- C：類似業種の1株(50円)当たりの年利益金額
- D：類似業種の1株(50円)当たりの純資産価額（帳簿価額）

が必要です。これは決算書に含まれない外部データで、国税庁ホームページ
「類似業種比準価額計算上の業種目及び業種目別株価等」で評価したい時点・
業種目のものを確認し、JSONの `similarIndustry.A/B/C/D` に入力してください。
未入力の場合、類似業種比準価額は0円として扱われ、併用方式は自動的に
純資産価額側に寄った評価になります（画面上に警告が表示されます）。

## 実装の前提・精度について（重要）

- **自社株評価**（類似業種比準価額・純資産価額・配当還元価額・併用方式・
  会社規模判定）は、財産評価基本通達178〜189-2に基づく標準的な算式で
  実装しています。比準要素数1/0の会社、株式保有特定会社、土地保有特定
  会社、開業後3年未満の会社等の特定会社判定は未実装です（原則的評価方式
  のみ）。土地・有価証券等の含み益がある場合は、各期データに
  `netAssetsTaxValueOverride`（相続税評価ベースの純資産額）を追加すると、
  含み益に対する法人税相当額(37%)控除を反映できます。
- **財務判定スコアリング**は、見本シート2社分の実際の「定量要因合計
  (129点満点)」と「財務判定(1〜7)」の数値（MYAP: 15→11→判定7／
  ZOU: 81→62→判定4）から、4区分（安全性34点・収益性15点・成長性25点・
  返済力55点）、100点換算、判定バンド（90/80/65/50/40/25点）の枠組みを
  検算の上で実装しています。一方、各指標の詳細な閾値（％と点数の対応）は
  見本画像からのベストエフォートでの転記であり、完全な一致は未検証です。
  `scoring.js` の `INDICATORS` を参照し、実際の与信判断に使う前に必ず
  原本と突き合わせてください。
- **必要保障額**（事業保障資金の試算）は、一般的な考え方（運転資金の
  必要月数、退職金の功績倍率等）に基づく初期値を設定していますが、
  ソニー生命独自の係数をそのまま復元したものではありません。
  `scoring.js` の `COVERAGE_DEFAULTS` で係数を調整してください。
  実効税率（`effectiveTaxRate`、既定値33.58%）によるグロスアップは、
  **負債等の返済資金（短期・長期）と自社株買取資金にのみ**適用します
  （＝(②③＋⑤) ÷ (1－実効税率)）。保険金でこれらを賄う場合、保険差益が
  益金算入され法人税等が課されるため、手取りの必要額を保険金ベースに
  割り戻す必要があるためです。一方、**①運転資金（＝固定費）はグロスアップ
  しません**。固定費はその年の損金として経費算入されるため、法人税の
  影響が相殺され、実額のままで必要保障額に合算します（退職金も同様に
  損金算入されますが、[参考]科目のため合計には含めていません）。
  就業不能時の運転資金は参考値として内部では算出しますが、本紙の表示
  からは除外しています（合計金額にも含めていません）。
- **キャッシュフロー計算書**は、中小企業の決算書に通常含まれる貸借対照表・
  損益計算書から、間接法で逆算しています（最も古い期間は前期の貸借対照表
  が無いため算出不可）。CF計と現預金の実際の増減（当期末残高－前期末残高）
  は、間接法による近似のため完全には一致しません。差異が無視できない場合
  （1,000円または現預金残高の0.5%のいずれか大きい方を超える場合）は
  「差異」注記を表示します。減価償却費（`pl.depreciationAnnualTotal`）が
  未入力の場合は0円として暫定計算し、「減価償却費未入力」の注記を表示します
  （推計値では埋めません）。
- **ギアリング比率・債務償還年数**は、分母が0以下（純資産が債務超過、または
  営業利益＋減価償却費が赤字）になると符号が反転し、見かけ上「良い数値」に
  化けてしまいます。この状態では `calc.js` の `gearingRatioValid` /
  `debtServiceYearsValid` が false になり、画面には実数値の代わりに
  「算出不可（債務超過）」「算出不可（営業赤字）」と表示し、スコアリングにも
  null（0点）として渡されます（符号反転による不当な高得点を防止）。
- **マイナス値の表記**は、全ページで `△123,456` 形式（赤字色）に統一して
  います（`app.js` の `fmt()`）。「〜減」のような接尾辞は使いません。
- **「未確認」と「0」の区別**：`data.preparedAssets`（準備済み資産）や
  `data.officers`（役員の最終報酬月額・在任年数）が未入力の場合、0円として
  断定せず「未確認」と表示します。必要保障額ページの不足金額も、準備済み
  資産が未確認の間は金額を確定表示せず「準備済み資産を確認後に確定」と
  表示します。

## サンプルデータの由来

- `sample-data/sample-zou.json`：実際の決算書（第1期・第2期）の貸借対照表・
  損益計算書・販管費明細を直接書き写した検証済みデータです。2期しか無い
  会社のため、ツールの「2期しか無い場合に3列表示へ変換するロジック
  （フロー項目はー表示、スナップショット項目は複製）」の動作確認に使えます。
- `sample-data/sample-myap.json`：ディスカッションシート見本（2025年期）に
  掲載された集計値（売上・粗利率・営業利益率・経常利益率・総資産・純資産等）
  から復元した概算データです。勘定科目の内訳レベルまでは元の決算書を参照
  できなかったため、流動資産・固定資産・流動負債・固定負債をそれぞれ
  1科目に単純化しています。実運用では科目別の内訳で入力し直してください。

```
discussion-sheet/
  index.html            画面本体
  style.css              スタイル
  app.js                 UI制御・描画
  calc.js                 財務比率・キャッシュフロー計算エンジン
  stock-valuation.js      自社株評価エンジン（財産評価基本通達ベース）
  scoring.js              財務判定スコアリング・必要保障額エンジン
  sample-data/            検証用サンプルJSON
```
