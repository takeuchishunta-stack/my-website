# note-kit

note の有料記事づくりと X 運用を、Claude API で半自動化するツールキット。

**リサーチ → ネタ出し → 執筆 → 品質チェック → X投稿文 → 投稿カレンダー** までを CLI で回す。

---

## 先に読んでほしい前提

このツールは「ボタンひとつで記事が量産されて勝手に売れる」ものではありません。実際にできること／できないことを最初に書いておきます。

| やりたいこと | 現実 |
| --- | --- |
| 記事の下書きを自動生成 | ✅ できる。ただし**あなたの一次情報を渡さないと一般論しか出ない** |
| 売れ筋のリサーチ | ✅ できる。note の公開検索データを読み取って集計する |
| 品質チェック・採点 | ✅ できる。機械チェック + AI採点で公開可否を判定 |
| X の投稿文生成 | ✅ できる |
| **note への自動投稿** | ❌ **できない。** note に外部から投稿する公式APIが無い。公開はブラウザから手動 |
| **X への自動投稿** | ❌ 本ツールでは行わない。X APIの制限と自動化ルールがあるため、生成した文面を手動 or 予約投稿する |
| 完全放置で収益化 | ❌ 無理。事実確認と最終判断は必ず人がやる必要がある |

そしてもう一つ、率直に言っておきます。

> **500円の記事は「量」では売れません。**
> note で有料記事が売れるのは、無料記事とXで信頼を積んだ後です。中身の薄い記事を大量に出すのは、note のアカウント評価的にも、あなたの信用的にも逆効果になります。
> このツールは「1本あたりの制作時間を1/5にして、その分を**質と本数の両立**に使う」ための道具として設計しています。品質ゲート（`review`）を外して回さないでください。

## セットアップ

```bash
cd note-kit
npm install
cp .env.example .env    # ANTHROPIC_API_KEY を書く
```

必要なもの:

- Node.js 20 以上
- Anthropic API キー（https://console.anthropic.com/ ）

**次にこれを必ずやる:**

```bash
open config/persona.md   # エディタで開く
```

`config/persona.md` は全ての生成プロンプトに読み込まれます。**ここの中身の濃さが、そのまま生成物の質になります。** 特に「6. 一次情報の在庫」は、思いついたときに書き足していってください。

動作確認:

```bash
npm test                      # ネットワーク不要のテスト
node bin/notekit.mjs status   # 設定と進捗の表示
```

## 全体の流れ

```
research  ──→  niche  ──→  ideas  ──→  write  ──→  review  ──→  x  ──→  plan
（市場調査）  （主戦場決定） （ネタ台帳） （本文生成） （品質判定） （X投稿文）（カレンダー）
                                          ↑                │
                                          └── 要修正なら戻る ┘
```

### 1. `research` — 何が有料で売れているかを調べる

```bash
node bin/notekit.mjs research                          # config/niches.json の全候補
node bin/notekit.mjs research --niche athlete-career --pages 3
node bin/notekit.mjs research --keyword "保険営業 辞めたい,営業 成果が出ない"
```

note の公開検索から、キーワードごとに **有料記事の比率・価格帯の分布・スキ数・上位アカウント** を集計して `data/market.json` に保存します。

- 1リクエスト1.5秒間隔。読み取りのみで、ログインも書き込みもしません。
- note には公式APIが無いため、レスポンス構造が変わると取得できなくなることがあります。その場合は `--keep-raw` を付けて `data/research/raw/` の中身を確認してください。

### 2. `niche` — 主戦場を決める

```bash
node bin/notekit.mjs niche
```

リサーチの実数値をもとに、候補ジャンルを5軸（需要 / 参入しやすさ / 収益化 / 自分との相性 / X相性）で採点し、`data/niche-report.md` に出します。

推奨だけでなく **「この判断が覆る条件」** も出力されます。データが薄いうちは鵜呑みにせず、自分の一次情報がある方を優先してください。

### 3. `ideas` — 売れる理由のあるネタを貯める

```bash
node bin/notekit.mjs ideas --count 12          # 有料記事のネタ
node bin/notekit.mjs ideas --count 6 --free    # 無料記事（集客用）のネタ
```

`data/ideas.json` が記事台帳になります。各ネタには

- `whyPaid`: なぜ無料部分だけでは足りないのか
- `requiredFacts`: **この記事を書くのに必要な、あなたの一次情報**
- `paidLineAt`: どの見出しの前で有料ラインを引くか

が付きます。`requiredFacts` が自分にないネタは、無理に書かないでください。中身のない有料記事は返金と信用低下に直結します。

### 4. `write` — 本文を書く

```bash
node bin/notekit.mjs write --id 2026-08-13-xxxxx --facts my-facts.md
```

**`--facts` が最重要です。** 自分の体験・数字・失敗をテキストにまとめて渡します（箇条書きで十分）。

```markdown
<!-- my-facts.md の例 -->
- 2020年4月、コロナ禍で入社。対面のアポが物理的に組めなかった
- 22歳の自分から保険に入る人はほぼいなかった。月収15万円の時期があった
- 知人リストが尽きた後、◯◯に切り替えたら紹介が出るようになった
- 練習が週◯日あるので、営業の時間は◯時〜◯時に固めている
```

保険・金融の方は、`config/persona.md` の「保険営業ならではの追加ルール」も必ず読んでください（商品名・収入額・顧客特定情報を書かない、副業規程の確認など）。

渡していない事実は、AIが勝手に体験談として書かないよう `【要追記: 〜】` というプレースホルダで残ります。**公開前に必ず自分で埋めてください。** これがこのツールの一番大事な安全装置です。

出力:
- `data/articles/<id>/article.md` — 本文（`<!-- ここから有料エリア -->` が有料ライン）
- `data/articles/<id>/meta.json` — タイトル案3本 / タグ / 価格 / 見出し画像の指示 / 販売文

### 5. `review` — 公開していいか判定する

```bash
node bin/notekit.mjs review --id 2026-08-13-xxxxx
```

2段階でチェックします。

**機械チェック**（AIを使わない確実な判定）
- 文字数・見出し数
- 有料ラインの位置と無料/有料の比率
- `【要追記】` の残り
- 景表法・薬機法まわりで危険な断定表現（`config/policy.json` の `riskyPhrases`）
- 禁止表現（「いかがでしたか」など）

**AI採点**（100点満点）
- 具体性 / 実行可能性 / 読みやすさ / 有料部分の価値 / 信頼性
- 「購入者が返金を求めるとしたらどこが理由になるか」も出力

80点以上かつ機械チェックにエラーが無ければ `ready`（公開可）になります。不合格なら `review.json` の修正指示を見て直し、もう一度 `review` を回してください。

### 6. `x` — X の投稿文を作る

```bash
node bin/notekit.mjs x --profile              # プロフィール・固定ポスト・最初の1週間
node bin/notekit.mjs x --id <id>              # 記事1本分の告知セット
node bin/notekit.mjs x --daily 10             # 記事に紐づかない日常運用ポスト
```

記事1本につき、**告知2案 / 8連投スレッド / 引用リポスト / 再告知3案 / 問いかけ** が出ます。
スレッドは「最後の1つ手前まで完全に無料で価値を出しきる」設計です。宣伝だけのアカウントは伸びません。

### 7. `plan` — 投稿カレンダーを組む

```bash
node bin/notekit.mjs plan --days 14
```

台帳の在庫状況から `data/calendar.md` を作ります（AIは使いません）。在庫が足りない場合は警告が出ます。

### `status` — いつでも現状確認

```bash
node bin/notekit.mjs status        # 進捗・API利用量・概算コスト
node bin/notekit.mjs status --all  # 台帳を全件表示
```

## 週次の運用ルーティン（推奨）

| 曜日 | やること | 所要 |
| --- | --- | --- |
| 月 | `plan` で今週の予定確認。`x --daily 10` で今週分のポスト在庫を作る | 15分 |
| 火・木・土 | note公開 → 告知ポスト → 翌日スレッド | 各30分 |
| 水 | `write` で次の記事の下書き → `--facts` を埋める | 60分 |
| 金 | `review` で校正 → 直す | 40分 |
| 日 | 反応（スキ・購入・流入元）を見て `config/persona.md` の一次情報を追記。月1で `research` を再実行 | 30分 |

最初の1ヶ月は**無料記事とXの投稿だけ**にして、フォロワーと反応を作ってから有料記事を出すのが結局いちばん早いです。有料記事は「この人の話をもっと聞きたい」が先にないと売れません。

## コストの目安

Claude Opus 5（既定）で、記事1本あたりのAPI利用料はおおよそ **$0.3〜0.8**（生成 + 採点）です。
月に記事12本 + ネタ出し + X投稿で **$10〜20 程度**。`status` で累計の概算が見られます。

安くしたい場合は `.env` で:

```
NOTEKIT_MODEL=claude-sonnet-5
NOTEKIT_EFFORT=medium
```

ただし記事本文の質は Opus のほうが明確に上です。**採点（`review`）だけは Opus のままにする**のがおすすめです（甘い採点をされると意味がないので）。

## 注意していること

- **note / X の規約**: 自動投稿はしません。読み取りも低頻度です。同一・類似記事の連投は note のスパム判定の対象になるため、`policy.json` で1日1本までに制限しています。
- **景表法・薬機法・金商法**: 「必ず稼げる」「病気が治る」等の断定表現を機械チェックで弾きます。ただし**最終的な法的判断はあなたの責任**です。検出されなかった表現が安全という意味ではありません。
- **著作権**: 他人の記事の要約を主コンテンツにしないでください。引用は出典明記で最小限に。
- **捏造しない**: AIに実体験を書かせないための仕組み（`--facts` と `【要追記】`）を必ず使ってください。バレたときに失うものが大きすぎます。

## ファイル構成

```
note-kit/
├── config/
│   ├── persona.md      ★ 書き手・読者・文体（最重要。まず埋める）
│   ├── niches.json       ジャンル候補とリサーチキーワード
│   └── policy.json       価格・文字数・品質基準・NGワード
├── data/                 生成物（gitで追跡される）
│   ├── market.json       リサーチ集計
│   ├── niche-report.md   ジャンル診断
│   ├── ideas.json        ★ 記事台帳
│   ├── articles/<id>/    本文・メタ・採点結果
│   ├── x/                X投稿文
│   └── calendar.md       投稿カレンダー
├── src/
│   ├── lib/              Claude/note/ストレージのラッパ
│   └── commands/         各コマンドの実装
├── test/                 ネットワーク不要のテスト
└── bin/notekit.mjs       CLI
```

## カスタマイズしどころ

| 変えたいこと | 触るファイル |
| --- | --- |
| 文体・トーン・禁止表現 | `config/persona.md` |
| 価格・文字数・無料部分の比率・品質基準 | `config/policy.json` |
| リサーチするジャンルとキーワード | `config/niches.json` |
| 記事の構成方針 | `src/commands/write.mjs` の `SYSTEM_BODY` |
| 採点の厳しさ | `src/commands/review.mjs` の `SYSTEM` と `policy.qualityGate.passScore` |
| Xの投稿スタイル | `src/commands/xposts.mjs` の `SYSTEM` |
